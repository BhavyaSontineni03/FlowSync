# Anomaly Scoring Model Evaluation

Generated by `train.py`. Data is split chronologically 60/15/25 into train/validation/test.

## Pipeline

1. **Isolation Forest** is fit on the training split's 6 features only. It never sees `is_anomaly`.
2. **Reviewer labels** are simulated on train+val: the top 20% of submissions by IF score go to review, plus a random 5% audit of the rest. That labeled 24.0% of train+val (1869 rows, 814 confirmed anomalies).
3. A **HistGradientBoosting calibrator** is fit on those labels, using the 6 features plus the IF score.
4. Headline metrics use a **12% flag rate** on the calibrator probabilities (review-queue size, not a value baked into the model).

Precision, recall, and F1 are measured once on the untouched test split.

## Versus the keyword / exact-match baseline

The baseline flags a duplicate only if the description contains a keyword such as "duplicate", or the amount matches a prior filing exactly. On near-duplicate resubmissions in the test set (amount nudged, description reworded, filed a few days later):

- Baseline recall: 0.00%
- This model recall on the same slice: 98.70%
